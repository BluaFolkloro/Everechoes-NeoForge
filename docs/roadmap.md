# 开发路线和计划

本文档记录 Everechoes 的近期开发方向。路线会随实现推进调整，不代表最终功能承诺。

## 阶段 0：基础内容整理

当前状态：进行中。

- 完成信件物品、邮筒和夜鹭手办的基础注册。
- 补齐模型、纹理、语言文件和创造模式标签页。
- 整理 README 和项目结构说明。
- 保持 `compileJava` 和 `build` 可用。

## 阶段 1：信件数据模型

目标：让三种信件物品可以共享一套明确的数据结构。

- 完善 `LetterData`。
- 明确 `DRAFT -> SEALED -> OPENED` 的单向状态流转。
- 明确退回地址、收件地址、标题、正文、落款和称呼的职责。
- 为 `LetterData` 设计 Data Component 存储方案。
- 设计序列化格式，供物品、网络同步和保存使用。

## 阶段 2：信件交互

目标：让玩家可以创建、编辑、封蜡和拆封信件。

- 为草稿信件实现编辑界面。
- 为蜡封信件实现只读外观信息。
- 为拆封信件实现阅读界面。
- 设计封蜡动作的触发方式。
- 设计从 `letter` 到 `sealed_letter`，再到 `opened_letter` 的物品转换。

## 阶段 3：邮筒系统

目标：让邮筒从占位容器变成实际投递入口。

- 替换当前邮筒占位 GUI。
- 限制邮筒可处理的物品类型。
- 实现基于 `Address` 的投递逻辑。
- 设计邮筒地址 `postalCode` 的生成、绑定和展示方式。
- 处理投递失败和退回逻辑。

## 阶段 4：多人和持久化

目标：保证邮件系统在服务器环境下行为稳定。

- 明确玩家地址和邮筒地址的解析规则。
- 设计服务器侧邮件数据存储。
- 处理离线玩家投递。
- 处理维度、区块卸载和邮筒被破坏的情况。
- 增加必要的同步包和权限检查。

## 阶段 5：体验完善

目标：补足可玩性、反馈和资源质量。

- 完善 GUI 视觉。
- 增加音效、粒子或提示反馈。
- 增加合成配方和掉落表。
- 增加测试用命令或调试工具。
- 清理 MDK 模板遗留配置。
